## 맥락

ops-api 는 운영자 커맨드를 코어 서비스 REST 로 위임한다(§5.5, 불변규칙 4 — 동기 REST 는 ops-api →
코어 방향만). 이번 묶음이 붙이는 것은 엔드포인트가 이미 있는 셋이다.

| 커맨드 | 코어 | 계약 문서 |
|---|---|---|
| 재계획 | dispatch `POST /api/v1/plans/{waveId}/run` | `contracts/openapi/dispatch-service.yaml` (Phase 6-0) |
| stop 재배정 | dispatch `POST /api/v1/routes/{routeId}/stops/{orderId}/reassign` | 같은 문서 |
| 주문 취소 | order `POST /api/v1/orders/{orderId}/cancel` | `contracts/openapi/order-service.yaml` |

Phase 6-0 이 dispatch 의 문서를 만든 이유가 이 클라이언트다 — 작업 1 을 먼저 했으면 위임 클라이언트는
컨트롤러 소스를 읽고 만들어졌고, 그 순간 §11 의 「문서가 계약이다」가 dispatch 에만 성립하지 않았다.
**ops-api 는 그 문장의 첫 소비자다.** 소비자가 문서를 읽고 만든 코드가 문서가 바뀌었을 때 깨지면, 그
문장은 검사가 된다.

## 결정

### 1. 생성을 시도한다 — 채택 기준은 시도 **전에** 여기 적는다

기준을 시도 뒤에 적으면 결과를 보고 기준을 고르게 된다. 그래서 이 절은 첫 생성보다 먼저 커밋한다.

**후보는 하나다**: openapi-generator 의 `spring` 생성기, `library=spring-http-interface`. 생성물이
`@HttpExchange` 인터페이스와 모델이고, 호출은 Spring Framework 7 의 `HttpServiceProxyFactory` 와
Boot 가 구성한 `RestClient` 가 한다 — HTTP 계층과 직렬화기를 생성물이 들고 오지 않는다. 같은 도구의
`java` 생성기(`library=restclient`)는 자기 `ApiClient` 와 Jackson `ObjectMapper` 를 생성물 안에 가져와
Boot 4 의 Jackson 3 과 둘째 직렬화기가 생긴다 — 후보로 삼지 않는다(**근거: 추정** — 생성해 보지 않았다).

**채택한다** — 아래가 전부 참일 때:

1. **표준 템플릿.** `templateDir` 를 쓰지 않고, 생성 뒤 파일을 고치는 후처리가 없다.
2. **설정은 생성기가 문서화한 옵션만.** `configOptions` 의 공개 키는 쓴다. `typeMappings`·`importMappings`
   로 생성물의 타입을 **이 저장소의 클래스로 바꿔 끼우는 것은 심(shim)으로 친다**.
3. **생성물이 그대로 컴파일된다.** 생성물에 이 저장소의 린트(`-Xlint:all … -Werror`)를 걸지는 않는다 —
   그것은 우리가 쓴 코드의 규약이지 호환의 기준이 아니다. 생성물은 **자기 컴파일 단계**를 가지고, 그
   단계가 경고를 내면 그 수를 이 ADR 에 적는다. 오류는 기각이다.
4. **Jackson 3 왕복이 통과한다.** 앱이 쓰는 `JsonMapper`(Boot 4 자동 구성)로 — 요청 모델은 직렬화한
   JSON 의 키가 계약 스키마의 속성 이름과 같고, 응답 모델은 계약 스키마대로 적은 JSON 을 역직렬화해 값을
   잃지 않는다. 호출 경로(`RestClient` + 프록시)를 한 번 거쳐서 본다.
5. **새 런타임 의존이 없다.** 생성물이 요구하는 라이브러리가 ops-api 의 클래스패스에 이미 있어야 한다
   (예: `jackson-databind-nullable` 이 필요하면 그것은 Jackson 2 모듈이라 호환 심이다 — 기각).

**기각한다** — 하나라도 거짓이면. 손댄 템플릿이나 심은 생성기 버전을 올릴 때마다 다시 깨지는 **두 번째
계약**이고, 그때는 손으로 쓴 인터페이스 + YAML 대조 테스트가 더 정직한 가드다. 그 대조 테스트는 §13
「서로를 비추는 목록에는 대조 검사를 둔다」의 한 자리가 된다 — 경로·메서드·파라미터·스키마 속성을
**YAML 에서 전부 읽고** 인터페이스의 것과 맞춘다(열거하지 않는다).

**채택하면 조건 셋**:

- 입력은 살아 있는 엔드포인트가 아니라 **커밋된 `contracts/openapi/*.yaml`** 이다. 생성 태스크는 그
  파일을 입력으로 선언한다 — 문서만 바뀐 빌드에서도 생성과 컴파일이 다시 돈다.
- 생성기 버전은 `gradle/libs.versions.toml` 에 고정한다.
- 생성물은 커밋하지 않는다 — `build/` 아래의 빌드 산출물이다.

### 2. 토큰은 스크립트가 찍고 ops-api 는 검증만 한다

설계에 사용자 저장소가 없다. 로그인 엔드포인트는 없는 것을 새로 만드는 것이고, 개발 프로필에서만 켜도
「프로필이 꺼져 있다」는 조용한 전제가 하나 는다. 그래서:

- 발급은 `make token ROLE=…` — 로컬 시크릿(환경변수)으로 HS256 토큰을 찍는다. **만료 12시간**: 데모
  토큰이 저장소나 스크린샷에 남았을 때의 반경이다.
- ops-api 는 서명·만료·역할 클레임만 본다. 시크릿이 없거나 짧으면(HS256 은 256비트) **기동하지 않는다** —
  열린 채로 뜨는 것보다 뜨지 않는 것이 낫다.
- ops-web 은 토큰을 붙여 넣는 설정 화면 하나로 충분하다. 그것이 「이 화면에는 인증이 있지만 사용자
  관리는 범위 밖」이라는 문장의 UI 판이다.

### 3. 감사 행은 위임 **전에** 쓰고, 결과를 모르면 `UNKNOWN` 이다

- 위임 전에 별도 트랜잭션으로 `PENDING` 행을 커밋한다. 순서가 반대면 위임과 기록 사이에 죽었을 때
  **기록이 사라진다** — 코어는 적용했는데 누가 했는지 아무도 모른다. 먼저 쓰면 적어도 `PENDING` 이 남는다.
- 결과는 넷이다: `SUCCEEDED`(2xx) · `REJECTED`(코어가 4xx 로 거절 — 적용되지 않았다) ·
  `FAILED`(연결 실패 또는 코어의 5xx — 적용되지 않았다) · **`UNKNOWN`**(응답을 받지 못했다 — 읽기
  타임아웃처럼 요청이 코어에 닿았을 수 있는 경우). **모름을 값으로 접지 않는다** — 타임아웃을
  `FAILED` 로 적으면 적용된 커맨드를 「안 됐다」고 말하게 된다.
- 감사 행의 id 를 코어 호출에 상관 헤더(`X-Dawnline-Audit-Id`)로 싣고, 코어는 그것을 로그 MDC 의
  `auditId` 로 남긴다. 사람이 `UNKNOWN` 행을 해소할 때 **어디를 볼지가 그 id 로 정해진다**.

## 고려한 대안과 기각 이유

- **생성 없이 처음부터 손으로 쓴 인터페이스 + 대조 테스트** — 결정 1 의 기각 분기다. 처음부터 고르지
  않은 이유는 가드의 세기다: 대조 테스트는 *테스트가 보는 것*만 지키고, 생성은 *컴파일이 보는 것*을
  지킨다. 계약이 바뀌면 컴파일이 깨지는 것이 이 저장소가 가진 가드 중 가장 센 형태다.
- **살아 있는 엔드포인트(`/v3/api-docs`)에서 생성** — 빌드가 코어의 기동에 매이고, 무엇을 입력으로
  썼는지가 커밋에 남지 않는다. 커밋된 문서가 계약이다.
- **생성물 커밋** — 문서와 생성물이 서로를 비추는 두 목록이 되고, 대조 검사가 하나 더 필요해진다.
- **ops-api 의 개발 전용 `POST /auth/token`** — 결정 2.
- **위임 뒤 한 번만 기록** — 결정 3.
