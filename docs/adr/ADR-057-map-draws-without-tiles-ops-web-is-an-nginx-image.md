## 맥락

설계서의 ops-web 문단은 「Leaflet + OpenStreetMap 타일 `[결정 필요: 타일 서버 정책상 데모 용도 확인]`」이었다(§17 목록
5). OSM 의 공개 타일 서버는 무료 CDN 이 아니다 — 이용 정책이 **표시(attribution)**, **적은 양**, **대량·선행 내려받기
금지**를 요구하고, 이를 어기는 사용은 차단될 수 있다. 그리고 이 저장소의 데모는 `make up` 하나로 서야 한다 — 타일이
인터넷에 기대면 오프라인 데모와 CI 에서 지도가 빈다.

화면을 누가 띄우는가도 같은 묶음의 질문이다. 서비스 다섯은 Buildpacks 이미지이고(ADR-013), ops-web 은 JVM 이 아니다.

## 결정

사용자 결정(2026-09-24)을 적는다.

### 1. 기본은 타일 없는 지도다 — OSM 은 데모용 선택

- **기본**: 타일 레이어가 없다. 배경은 무늬 없는 면이고, 좌표는 **캠프 중심**이다 — 창고(`rm_waves.depot_*`, 없으면 stop
  들의 중심)를 가운데 두고 stop 들이 들어오게 맞춘다. 도로는 없다. 그려지는 것은 창고 · stop(순서 번호, 상태 색) · 순서
  폴리라인(창고에서 나가 창고로 돌아온다) · at-risk 강조다. 이것만으로 「어느 stop 이 어느 순서로 어디쯤」이 읽힌다 —
  재배정과 조기 마감을 판단하는 데 도로는 필요 없다.
- **OSM 타일은 설정에서 켠다** — 데모 용도, 적은 빈도, 표시와 함께. 켜도 브라우저 세션 하나의 선택이고(저장소나 서버의
  설정이 아니다), 기본값을 바꾸지 않는다. 선행 내려받기·캐시 서버는 두지 않는다.
- **타일이 안 와도 화면은 깨지지 않는다.** 켠 상태에서 타일 요청이 실패하면(오프라인·차단) 지도는 타일 없는 모양으로
  그대로 그리고, 「타일을 불러오지 못했다」를 한 줄 알린다. **증명은 컴포넌트 테스트다** — 타일을 켜고 모든 타일이
  실패하게 한 뒤 stop · 폴리라인 · 명령이 그대로 있는지 본다.

**기각**: OSM 을 기본으로(오프라인 데모가 빈 지도가 되고, 데모마다 공개 서버를 두드린다) · 자체 타일 서버·벡터 타일
(데모 하나를 위해 수 GB 의 타일과 서버 하나가 는다) · 상용 타일 API(키가 저장소에 들어오거나, 없으면 데모가 서지 않는다).

### 2. ops-web 은 nginx 이미지 하나다 — Buildpacks 가 아닌 유일한 이미지

- 다단 빌드: `node`(`.nvmrc` 의 24)에서 `npm ci` → 커밋된 `contracts/openapi/ops-api.yaml` 에서 타입 생성 → `tsc` →
  `vite build`, 결과를 `nginx` 가 서빙한다. 두 이미지의 판은 `deploy/compose/.env.example` 에 고정한다(`NODE_IMAGE` ·
  `NGINX_IMAGE`) — 다른 인프라 이미지와 같은 자리다.
- **같은 출처**: nginx 가 `/api/` 를 ops-api 로 넘긴다. ops-api 에 CORS 를 열지 않는다 — 열면 「어느 출처가 허용되는가」가
  운영 설정 하나 더가 되고, 토큰을 싣는 요청이 교차 출처가 된다.
- **프록시는 두 헤더를 그대로 통과시켜야 한다**: 요청의 `Authorization`, 응답의 `X-Dawnline-Audit-Id`. 앞의 것이
  빠지면 모든 조회가 401 이고, 뒤의 것이 빠지면 운영자가 `UNKNOWN` 감사 행을 해소할 id 를 잃는다(ADR-052 결정 3).
  **이 둘은 컴포넌트 테스트가 아니라 Compose 스모크가 본다**(묶음 C3) — 컴포넌트 테스트에는 nginx 가 없다.
- **Compose 스모크의 빌드 대상에 들어간다**: `make images` 가 서비스 다섯의 Buildpacks 이미지와 함께 이 이미지를 만든다.
  CI 의 스모크 job 은 `make images` 를 부르므로 이 이미지의 빌드가 깨지면 스모크가 빨갛다 — **꺼 둔 job 의 결함은 켜기
  전까지 보이지 않는다**(CLAUDE.md 「빼는 방식」의 셋째 사례, 스모크 job 의 `needs`).

**대가 — 이 저장소의 이미지 규칙에 예외가 하나 생긴다.** ADR-013 이 Buildpacks 를 고른 이유(Dockerfile 을 손으로
관리하지 않는다, 기반 이미지 갱신을 빌더가 맡는다, 레이어가 재현 가능하다)가 이 이미지에는 없다: Dockerfile 하나와
nginx 설정 하나를 손으로 관리하고, 기반 이미지 갱신은 `.env.example` 의 두 줄을 사람이 올린다. Phase 7 의 「컨테이너
이미지 빌드」 job(서명·SBOM 을 붙일 자리)은 이 이미지를 따로 다뤄야 한다 — 그때 이 ADR 을 가리킨다.
Buildpacks 의 Node·nginx 빌드팩으로 맞추는 안은 **기각** — 정적 파일 서빙과 한 경로의 프록시를 위해 빌더 구성을 하나 더
들여오게 되고, 「`/api` 를 넘긴다」는 두 줄이 빌드팩 설정 속으로 숨는다.

**`make up` 만으로 화면이 뜬다**는 것이 요건이다. 「Node 가 설치되어 있다」는 조용한 전제는 기각했다(사용자 결정) — 개발
서버(`npm run dev`)는 화면을 고치는 사람의 도구이고 데모의 경로가 아니다.

### 3. 화면은 둘이다

캠프 대시보드(웨이브 · 계획 · 정시율 두 기준 · 개정 수 · 예외 목록)와 라우트 지도(stop 순서 폴리라인 · 상태 색 ·
at-risk 강조 · 재배정 · 조기 마감). 룰 편집은 Swagger, 설정은 토큰 붙여 넣기 하나(IMPLEMENTATION_PLAN 의 축소안).
화면의 입력은 계약에 있는 칸만이다(ADR-056 결정 2).
