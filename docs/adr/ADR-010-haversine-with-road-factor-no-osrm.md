# ADR-010 — 거리는 하버사인 × 도로계수다 · OSRM 어댑터는 만들지 않았다

| 항목 | 내용 |
|---|---|
| 상태 | Accepted (2026-09-28 — Phase 3 에 계획했고 쓰지 않았던 ADR 을 구현된 사실에서 쓴다) |
| 결정일 | 2026-09-28 (구현은 Phase 3, 2026-09-05) |
| 관련 문서 | `docs/DESIGN.md` §6.2(`DistanceProvider`) · §7.2(`dist:*`) · §15(위험) |
| 관련 ADR | [ADR-004](ADR-004-compare-against-the-boundary-not-another-solver.md) (새 기술을 도입하지 않는 결정의 형식) |

---

## 맥락

최적화는 거리 · 시간 행렬 위에서 돈다. `DistanceProvider` 는 `(a, b) → (meters, seconds)` 인터페이스이고, 구현은 `HaversineDistance` 하나다 —
`Haversine.meters × roadFactor`, 시간은 평균 속도에서. 설계서는 선택 구현 `OsrmDistance`(테이블 API · 캐시)를 적었지만 **만들지 않았다.**

## 결정

1. **기본이자 유일한 구현은 하버사인 × 도로계수 1.3 · 평균 25 km/h 다.** 벤치마크와 서비스가 같은 구현을 쓴다(순수 도메인 — 불변규칙 5).
   `Travel` 이 거리와 시간을 함께 돌려주는 것은 OSRM 이 시간을 직접 주기 때문에 남긴 자리다.
2. **값은 서비스 설정이지 캠프 설정이 아니다**(`dawnline.dispatch.distance.road-factor` · `average-speed-kmh`). 설계서의 「캠프 설정값」은 정정한다 —
   캠프 표에 그 칸은 없다.
3. **OSRM 어댑터는 만들지 않는다.** 이 포트폴리오가 재는 것은 알고리즘의 상대 비교(같은 거리 함수 위의 전략 대 전략 · 불가능의 경계)이고,
   도로망의 절대 거리는 그 비교를 바꾸지 않는다. 거리 캐시는 하버사인에서 **6–7배 느리고 답을 바꿨다** — 지웠다(근거: 관측 — `phase3-baseline.md`).
   OSRM 이면 캐시가 필수라 그 측정을 다시 해야 한다.

## 대안

| 안 | 기각 사유 |
|---|---|
| OSRM 어댑터 + `dist:{gh7a}:{gh7b}` 캐시 | 별도 서버 · 지도 데이터 · 캐시 무효화가 는다. 상대 비교가 바뀌지 않는다 |
| 상용 지도 API | 비용 · 키 관리, 벤치마크 재현성(외부 응답)이 깨진다 |
| 캠프별 도로계수 | 근거가 될 실측이 없다 — 정해 둘 수가 없다 |

## 재검토 지점 (포트폴리오 범위 밖 — 다시 여는 조건)

- **절대 시각이 약속이 될 때** — 예정 도착을 고객에게 보이거나, 지각 판정이 실제 도로 시간과 어긋나 at-risk 가 잦아질 때(편차의 분포가 증거다).
  그때 OSRM 으로 한 번 검증하고(DESIGN §15), 도로계수를 캠프별로 보정한다.
