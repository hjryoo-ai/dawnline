## 맥락

§10 은 **고객 주문 API** 를 무인증으로 두었다. 근거는 「인증이 이 포트폴리오가 증명하려는 것(멱등·상태 머신·
경로 최적화)에 아무것도 더하지 않는다」였고, 운영자 쪽 보안은 ops-api 의 JWT + 역할 + 감사가 맡는다.

그 두 문장 사이에 칸이 하나 비어 있었다. ops-api 가 위임하는 커맨드의 **코어 쪽 끝**이다. 운영자는 ops-api 를
거쳐 코어를 부르고 ops-api 는 위임 **전에** 감사 행을 남긴다(ADR-052). 그런데 코어의 그 엔드포인트는 코어의
포트에 무인증으로 열려 있다 — ops-api 를 거치지 않고 부르면 **같은 커맨드가 감사 없이 적용된다.** 2026-09-24
기준으로 그런 쓰기가 열 개였다:

| 코어 | 쓰기 |
|---|---|
| fulfillment | `POST /api/v1/waves/{waveId}/close` |
| dispatch | `POST /plans/{waveId}/run` · `PUT /rules/{ruleId}` · `POST /vehicles` · `POST /drivers` · `POST /routes/{routeId}/stops/{orderId}/reassign` |
| 코어 넷 | `POST /api/v1/admin/outbox/{id}/requeue` (ADR-015 후속 정정) |

근거: 관측(재현됨) — 이 ADR 의 검사(아래 결정 3)에서 인터셉터 등록을 빼고 돌리면 네 서비스의
`OpenApiContractIT` 가 위 쓰기를 전부 「토큰 없이 401 이 아니다」로 나열한다. 기존 IT 들(`DispatchAdminIT`
의 `PUT /rules` 등)이 아무 헤더 없이 성공하던 것도 같은 사실이다.

이것이 처음 드러난 것은 outbox 재큐였다. ADR-015 후속 정정은 ops-api 에 그 엔드포인트를 **끈** 이유로 「감사 행
없는 재큐가 생긴다」를 들었고, 같은 근거로 order-service 의 관리 경로를 재검토 지점(근거: 추정)에 남겼다. 그러나
그 근거는 경로 접두어(`/admin/`)의 성질이 아니라 **호출자와 커맨드의 성질**이다 — 그리고 그 성질을 가진 쓰기는
재큐 하나가 아니었다.

## 결정

### 1. 정의 — 운영자 쓰기 커맨드는 경로가 아니라 호출자와 성질로 정한다

**ops-api 만 부르고, 쓰기이며, ops-api 가 감사 행을 남기는 커맨드.** 이것들은 내부 토큰을 요구한다.

규칙은 **기본 거부**로 적는다: 코어의 모든 `POST`·`PUT`·`PATCH`·`DELETE` 는 토큰 대상이고, 예외는 **고객·현장
표면의 명시 목록** 셋뿐이다.

| 면제 | 서비스 | 이유 |
|---|---|---|
| `POST /api/v1/orders` | order | 고객 주문 API — §10 의 의도된 무인증 |
| `POST /api/v1/orders/{orderId}/cancel` | order | 같은 고객 표면. ops-api 의 `CANCEL_ORDER` 도 이 경로로 위임한다 — 아래 「결과」 |
| `POST /api/v1/routes/{routeId}/stops/{stopSeq}/events` | tracking | 현장(기사 단말) 스캔 — 단말 인증은 범위 밖 |

열거하는 쪽이 **면제**라는 것이 요점이다(CLAUDE.md 「집합을 도는 검사는 열거하지 않고 전체에서 뺀다」). 새 쓰기
엔드포인트는 아무것도 적지 않으면 토큰 대상이 된다 — 열린 쪽으로 새려면 누군가 면제를 **적어야** 한다.

`GET` 은 대상이 아니다. 감사 대상이 아니고, 토큰을 읽기에까지 걸면 sim-runner·k6·데모 스크립트가 그것을 실어야
하는 비용만 생기지 막는 것이 없다. 읽기 표면의 노출은 §9.3(주소 전문 없음)이 다루는 문제다.

### 2. 장치 — 헤더 하나, 상수 시간 비교, 매핑 뒤의 인터셉터

- **헤더 `X-Dawnline-Internal`** 이 `DAWNLINE_INTERNAL_TOKEN`(서비스 공통 하나)과 같아야 한다. 비교는
  `MessageDigest.isEqual`(상수 시간)이다. 없거나 다르면 **401 `internal-token-required`** — 둘을 구별하지
  않는다(응답은 어느 쪽이 틀렸는지 말하지 않고, 로그만 말한다).
- **`libs/web` 의 `HandlerInterceptor`** 이고 서블릿 필터가 아니다. 두 이유다.
  - **면제는 핸들러 단위의 사실이다.** 경로 문자열 목록으로 적으면 경로 템플릿·버전 세그먼트와 대조하는 두 번째
    라우터가 생긴다. 인터셉터는 매핑이 끝난 핸들러를 받으므로 면제 표시를 **핸들러 메서드의 어노테이션**
    (`@UnauthenticatedWrite(reason = …)`)으로 읽는다. 이유 칸은 필수다 — 면제는 읽혀야 한다.
  - **매핑 뒤에 선다.** 모르는 경로는 404, 지원하지 않는 버전은 400 으로 남는다(ADR-009). 필터가 앞에 서면
    둘 다 401 이 되고, 「그 경로가 있다」를 토큰 없는 사람에게 말하지 않는 대가로 오류 계약이 흐려진다.
- **401 은 다른 오류와 같은 문을 지난다.** `preHandle` 은 전용 예외(`InternalTokenRejectedException`, 
  `DomainException` 하위)를 던지고 `ProblemDetailsAdviceSupport` 가 Problem Details 로 만든다. 인터셉터가 응답을
  직접 쓰면 「4xx 본문은 Problem Details」라는 오류 본문 계약에 예외가 하나 생긴다.
- **토큰이 없거나 32바이트보다 짧으면 기동하지 않는다** — ops-api JWT 시크릿과 같은 규칙이다. 빈 토큰으로 뜬
  서버는 전부 거부하거나(조용히 막힘), 비교를 잘못 쓰면 전부 받는다(조용히 열림). 뜨지 않는 것이 둘보다 낫다.
- 컨트롤러 메서드가 아닌 핸들러는 둘로 나뉜다. 정적 자원 핸들러는 `GET`·`HEAD` 만 받으므로(쓰기는 405) 통과시키고,
  **그 밖의 핸들러 타입은 토큰을 요구한다**(기본 거부) — 이 저장소에 함수형 엔드포인트는 없지만, 생기는 날 열린
  쪽으로 새지 않는다. 오류 디스패치(`/error` 로의 전달)는 검사하지 않는다 — 원래 요청이 이미 한 번 지났다.

### 3. 강제 수단은 문서에서 뽑는 IT 다 — 인터셉터의 등록 여부와 무관하게

`InternalTokenSurfaceContract`(`libs/web` testFixtures)를 코어 넷의 `OpenApiContractIT` 가 구현한다.

- **문서에서 뽑는다.** 생성된 OpenAPI 문서에서 `GET` 이 아닌 오퍼레이션을 **전부** 읽어 헤더 없이, 그리고 틀린
  헤더로 부르고 401 `internal-token-required` 를 기대한다. 면제 목록에 있는 것만 예외다. 인터셉터가 어느
  서비스에서 등록이 빠지면 그 서비스의 쓰기가 조용히 열리는데, 이 검사는 **장치가 아니라 결과를** 보므로 그것을
  잡는다.
- **면제는 읽힌다.** `@UnauthenticatedWrite` 가 붙은 핸들러 집합과 IT 가 선언한 면제 목록을 대조한다. 누가 새
  핸들러에 면제를 붙이면 목록에도 적어야 초록이 된다 — 「쓰인 제외는 읽힌다」의 이 자리 판이다. 면제 목록의
  오퍼레이션이 문서에 있다는 것과 토큰 없이 401 이 **아니라는** 것도 함께 본다(면제가 살아 있다).
- **문서도 말한다.** 토큰 대상 오퍼레이션에는 보안 요구 `internalToken`(apiKey · header)이 붙는다. 검사는
  「문서가 토큰을 요구한다고 말하는 집합 = 401 을 받는 집합」도 본다.
- 이것은 ArchUnit 규칙이 아니다(§13). 규칙 8 처럼 어노테이션의 *자리*를 보는 검사는 「면제가 붙었는가」까지는
  보지만 「그 서비스에서 장치가 실제로 도는가」는 볼 수 없다.

### 4. ops-api 는 모든 코어 호출에 헤더를 싣고, 자기 쓰기에는 장치를 끈다

- 헤더는 감사 id 상관 헤더와 같은 자리(`RestClient` 그룹 인터셉터)에서 **모든 그룹의 모든 호출**에 싣는다.
  위임 셋(재계획·재배정·취소)이 이 PR 과 함께 헤더를 싣는다 — 빠지면 머지 직후 기존 커맨드가 401 로 깨진다.
  취소는 면제 경로라 헤더가 필요 없지만 싣는다: 「어느 호출에 싣는가」를 호출마다 고르는 규칙은 새는 규칙이다.
- 생성된 인터페이스에 헤더 파라미터를 끼우지 않는다(ADR-052 기준 2) — 문서의 보안 요구는 생성기가 파라미터로
  만들지 않는다(빌드로 확인).
- ops-api 자신은 `dawnline.web.internal-token.enforce=false` 다. 그 쓰기는 JWT + 역할 + 감사가 지킨다. 그래도
  토큰 값은 바인딩한다 — 없거나 짧으면 ops-api 도 뜨지 않는다(코어를 부를 수 없는 ops-api 는 뜨지 않는 편이
  낫다). `OpsCommandIT` 가 전제(`libs/web` 이 붙어 있다) → 부재(인터셉터가 없다) 순으로 본다.

### 5. 값은 `make env` 가 채운다

`DAWNLINE_INTERNAL_TOKEN` 은 `make env` 가 `.env` 를 만들 때 무작위(`openssl rand -hex 32`)로 채우고, 예전
`.env` 에 없으면 덧붙인다. `.env.example` 에는 자리표시자만 있다(32바이트 이상 — CI 의 Compose 스모크가 그것을
그대로 쓴다). Compose 가 코어 넷과 ops-api 에 같은 값을 넘긴다.

## 고려한 대안

- **outbox 관리 경로에만.** 처음 요청된 범위다. 그 근거(「감사 행 없는 쓰기가 생긴다」)는 조기 마감·재계획·룰
  수정·자원 등록·재배정에 그대로 적용된다 — 한 경로에만 쓰면 같은 근거를 한 번만 쓴 것이다.
- **읽기까지(고객·현장 외 전부).** sim-runner 가 dispatch 의 `GET /plans`·`GET /routes` 를 직접 부른다. 막는 것
  없이 도구 셋에 토큰을 실어야 하는 비용만 생긴다.
- **서블릿 필터 + 경로 목록.** 면제를 경로 문자열로 적으면 버전 세그먼트·경로 변수와 대조하는 라우터가 하나 더
  생기고, 필터가 매핑 앞에 서서 404·400 이 401 이 된다.
- **코어에 Spring Security.** 다섯째 보안 표면(필터 체인·예외 번역·CSRF 설정)이 코어 넷에 생긴다. 필요한 것은
  헤더 비교 하나다.
- **네트워크 경계만(Compose 네트워크·실서비스 전환 시).** 호스트 포트가 열려 있는 한 지금은 막는 것이 없고,
  「전환할 때 막는다」는 추정으로 남는 약속이다. 한 줄로 지금 막는 것이 싸다.
- **서비스별 토큰.** 새는 반경은 줄지만 ops-api 가 네 값을 알아야 하고 `make env` 가 넷을 만든다. 이 범위에서
  사는 것이 없다 — 아래 재검토 지점.
- **인터셉터가 401 을 직접 쓴다.** 오류 본문 계약의 예외가 하나 생긴다.

## 결과

- **장점**: ops-api 를 거치지 않는 운영자 쓰기가 코어에서 거부된다 — 「모든 커맨드는 `audit_logs` 에
  기록」(§5.5)이 코어 쪽에서도 참이 된다. 새 쓰기 엔드포인트는 기본으로 닫혀 있다.
- **비용**
  - 보호 대상 쓰기를 부르는 테스트가 헤더를 싣는다(코어 IT 와 `libs/messaging` 의 `OutboxQuarantineIT`).
  - 토큰이 하나라서 한 서비스에서 새면 전 코어의 운영자 쓰기가 열린다. 그리고 **코어도 그 값을 안다**(검증하려면
    알아야 한다) — 코어가 다른 코어의 운영자 쓰기를 부르는 것을 막는 것은 이 토큰이 아니라 불변규칙 4 다.
  - **주문 취소는 고객과 운영자가 같은 경로를 쓴다.** 코어는 둘을 **상태에서** 구별하지 못하고, 운영자 취소의
    감사는 ops-api 쪽에만 있다 — 고객이 직접 취소한 것은 감사 대상이 아니다(고객 행동이다). **로그에서는
    구별된다**: ops-api 의 위임은 `X-Dawnline-Audit-Id` 를 싣고 코어의 `MdcFilter` 가 그것을 MDC `auditId` 로
    남긴다(§9.3) — 그 칸이 있는 취소 로그는 운영자의 것이고, 없는 것은 고객의 것이다.
  - 토큰을 바꾸려면 코어 넷과 ops-api 를 다시 띄운다.
- **되돌리는 방법**: 서비스의 `dawnline.web.internal-token.enforce=false`. 다만 그 서비스의
  `OpenApiContractIT` 가 빨개진다 — 되돌리는 사람은 이 ADR 을 읽게 된다.

## 추가 — 거부를 센다 (2026-09-24, 작업 2 의 마지막 PR)

`dawnline_internal_token_rejected_total{service, reason}` — `reason` 은 `missing`·`mismatch`, `service` 는 공통
태그다(§9.1). 인터셉터가 거부를 던지기 직전에 올린다(트랜잭션이 없는 자리라 「커밋 뒤에 센다」가 걸릴 것이 없다).

**0 이 아니면 「ops-api 를 거치지 않는 누군가」다.** 레이트 리밋의 `bypassed`(§7.2)와 같은 부류의 신호 —
**보상 통제가 뚫리는 것을 세는 카운터**다. 레이트 리밋은 무인증 고객 API 의 남용 방지이고 그것이 꺼진 순간을
`bypassed` 가 알리듯, 내부 토큰은 운영자 쓰기의 감사를 코어 쪽에서 참으로 만드는 장치이고 그것을 두드리는 요청을
이 카운터가 알린다. 알림은 `> 0`(§9.4) — 정상 운영에서 이 값은 0 이다: ops-api 는 모든 호출에 토큰을 싣고, 고객·
현장 표면은 면제라 여기에 오지 않는다. 로그 한 줄(`reason`·경로)은 이미 있었다 — 로그는 **찾을 때** 읽히고
카운터는 **찾지 않아도** 울린다.

## 재검토 지점

- **실서비스 전환 시** 공유 토큰을 서비스 간 mTLS 또는 서비스별 자격으로 바꾼다. 그때도 「기본 거부 + 읽히는
  면제」와 「문서에서 뽑는 검사」는 남는다 — 바뀌는 것은 헤더 비교 한 줄이다.
- **현장 스캔의 단말 인증**은 범위 밖이다(§10). 스캔이 운영 쓰기처럼 쓰이기 시작하면(예: 운영자가 스캔을 대신
  넣는 화면) 면제를 다시 본다.
